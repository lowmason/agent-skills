### R3 — The runner: `build/run_suites.py`
S79. R3.1 Stdlib only (`tomllib`, `argparse`, `subprocess`, `shlex`), Python 3.13.
S80. Invoked as `uv run --python 3.13 python build/run_suites.py …` from any directory.
S81. It finds the repo root from its own path, never from the working directory.
S82. R3.2 **One run** is one interpreter of one suite.
S83. Its command is `uv run --python <python> --with <dep> … python -m pytest -q [<args>]`, run with the suite's `dir` as its working directory.
S84. Its shell form is `cd <dir> && <command>`, with shell quoting where a word needs it.
S85. With default options, the shell form equals the suite's current `CLAUDE.md` command, character for character.
S86. For `hooks`, whose line chains two runs as `cd hooks && A && B`, the two shell forms are `cd hooks && A` and `cd hooks && B`.
S87. R3.3 **`--list [NAME …]`** prints, for each named suite (default: all): its name and directory, the shell form of each run, its extras, and its notes.
S88. `--extras` and the `--` arguments apply here too, so `--list` prints the exact command that a run would use.
S89. R3.4 **`NAME [NAME …]`** runs the named suites, in the order given, one run per interpreter in `pythons`.
S90. Each run starts with a `== <name> (<python>)` header, and the suite's notes follow its first run's header.
S91. Then pytest's output streams.
S92. A failed run does not stop the next one.
S93. R3.5 **`--extras`** adds each suite's `extras` after its `with` deps.
S94. Arguments after **`--`** go to pytest (a test node ID, `-k`, `-s`, `-rs`) in every run.
S95. R3.6 **`--all`** runs every suite except one whose `dir` lies inside another suite's `dir`.
S96. Today that is `cc-guide`: `cd build && pytest` collects `build/cc_guide` already.
S97. `--all` prints one line for each suite that it skips.
S98. A suite named on the command line always runs.
S99. R3.7 **Exit status:** 0 when every run exits 0; 1 when any run fails (pytest's exit 5, no tests collected, counts as a failure); 2 for a usage error, an unknown suite name, or a registry that fails validation.
S100. The last line names the failed runs, or says that every run passed.
S101. A run whose `uv` cannot start counts as failed.
S102. R3.8 The runner passes its environment to every run unchanged.
S103. `CALIBRATION_SWEEP=1 uv run --python 3.13 python build/run_suites.py bayesian-workflow -- -s` therefore runs the sweep.
S104. R3.9 Validation fails closed.
S105. An unknown key, a missing required key, a wrong type, a duplicate name or directory, or a `with` list without `pytest` stops `--list`, a named run and `--all` with exit 2.
S106. `--check` reports the same failures as findings (R4.3).
S107. A misspelled key can therefore never run a suite without its deps.

### R4 — The guard: `run_suites.py --check`
S108. R4.1 `--check` reports two kinds of findings:
S109. - **registry:** R3.9's validation, plus a registered `dir` that does not exist or holds no pytest file;
S110. - **coverage:** a directory that holds a pytest file (`test_*.py` or `*_test.py`, pytest's default patterns) and does not lie inside any registered `dir`.
S111. R4.2 The file list is `git ls-files --cached --others --exclude-standard`, run at the repo root.
S112. Ignored trees, `.claude/worktrees/` and `build/.scratch/` among them, drop out.
S113. Untracked new suites count, as the hook's other lints read untracked drafts too.
S114. If git fails, `--check` fails.
S115. R4.3 Output: `suite registry ok` and exit 0, or one line per finding and exit 1.
