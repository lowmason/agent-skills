### Frictions found — real-world, worth recording as findings

These are exactly what a synthetic fixture would never surface:

1. **Naming mismatch breaks mode selection.** The skill selects Synthesize
   mode when `specs/<name>-critique.md` sits beside
   `specs/<name>-methodology.md`. Actual files use underscores and
   `_review` (`usable_series_methodology.md` /
   `usable_series_methodology_review.md`). The rule as written would NOT
   fire. Either loosen the rule (match `*review*` / `*critique*` beside a
   `*methodology*` file) or treat the naming as a convention the handoff
   message must enforce.
2. **No routing header** — the review predates the skill, so it was not
   produced with `references/critique-prompt.md`. MT2 showed the
   frontmatter description alone routes 5/5, so this is survivable, but
   it means the header cannot be assumed present on real inputs.
3. **Critique points are not `C1..Cn`.** They are §1–§10 plus
   Recommendations 1–9. `spec-synthesis.md` says "Number every critique
   point (C1, C2, …) so a downstream triage table can cite them" — the
   triage table needs a locator scheme for un-numbered real critiques
   (proposal: cite `§N` and `R#`).
4. **Adjudication status unknown.** The skill's prompt asks Chat to record
   *adjudicated* positions after interactive push-back. Unknown whether
   the user pushed back or took the first pass. Ask before triaging —
   "reject" verdicts inherit differently depending on the answer.
