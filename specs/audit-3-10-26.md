## G — Generality: do the lifecycle skills serve every model the producer skills make?

### The premise, measured

"alt-nfp" appears **0 times** in `tune-hyperparameters` and `track-model-experiments`, and Regime A's only worked example is a sklearn `Ridge`. So the skill is not literally Bayesian-only or alt-nfp-only. What makes it read that way is wording that **restricts scope**:
- **The description.** It triggers on "learning rate for a nowcasting/tabular model" (`tune-hyperparameters/SKILL.md:5-6`), and its only CV trigger is time-series, rolling-origin or purged CV (`:7-9`).
- **The CV protocol.** The only one is forward-chaining (`:57`).
- **Regime B.** It names only NUTS, SVI and "dynamax optax" (`:138-146`).
- **Step 0.** It is a binary A/B split with no slot for structural or evidence-based choices (`:36-43`). Line `:119-120` excludes anything that is "part of a Bayesian model" without naming an owner.
- **Graduation.** It routes the winner into a comparator that reads only `InferenceData`.

Two things are acceptable example *flavor*, not restrictions: the revision-leakage caveat (`:159-166`) and the Ridge example.

**Who produces models.**

#### G1 — Graduation silently drops non-Bayesian winners and stamps `**best**` anyway

**Where.**
- `tune-hyperparameters/SKILL.md:124-131` and `track-model-experiments/SKILL.md:43-45`: the documented handoff.
- `track-model-experiments/scripts/compare_experiments.py`: `:18` discovers only `*/inference_data.nc`; `:22` loads it; `:257` catches only `ValueError`.

**Evidence.** Re-measured by both the reviewer and the verifier. The fixture ledger held two NumPyro variants plus a row written exactly as tune's Graduation section prescribes ("tuned `Ridge` via Optuna, 50 trials, alpha"):
- With auto-discovery, the result was exit 0 and the ranking `['bayes-v2', 'bayes-v1']`. `**best**` was stamped on bayes-v2, and the Ridge row stayed `candidate`, never compared.
- With `--folders bayes-v2 ridge-tuned`, the result was exit 1 with a raw `FileNotFoundError` traceback rather than the script's `error:` path.
- The ledger has no column for a CV score (`track SKILL.md:67`).

**Update.**
1. The comparator reads the ledger's ids and reports any row it did not compare. While such a row exists, it either refuses to move `**best**` or labels the marker "best among ELPD-compared variants".
2. Route `FileNotFoundError` and `az.compare`'s `TypeError` through `error:`.
3. Add one sentence each to tune's Graduation section and track's When-to-use: until a non-ELPD mode exists, a graduated non-Bayesian winner is recorded in the Decision log with its CV score.
4. Add tests for both paths.

**Route:** small · plan · open on main. This revisits track spec D3 ("do not build the ML half now"): tune then shipped a path that depends on that unbuilt half.

#### G2 — The bundled splitter splits rows, not periods, so panels leak, and so does the sklearn advice

**Where.**
- `tune-hyperparameters/scripts/time_series_cv.py:54-71`.
- `SKILL.md:53`, which names "a panel" as covered, and `:60-62`, which says sklearn's `TimeSeriesSplit` "already suffices".
- `SKILL.md:71`: a bare `from time_series_cv import …` that resolves only from inside `scripts/`.

**Evidence.** Two independent fixtures were used: 3 entities × 10 periods, and 3 series × 20 periods sorted by period.
- `PurgedTimeSeriesSplit` put the same period in train and validation in 2 of 5 folds. Its `embargo` counts rows, so `embargo=2` left a whole-period gap of 0.
- sklearn `TimeSeriesSplit(gap=1)` shared the same periods.

**Update.**
1. Add a `time` or `groups` argument. Split on sorted unique periods, measure `test_size`, `embargo` and `label_horizon` in periods, and map back to rows.
2. Add a panel test asserting that no period appears in both train and validation.
3. Limit the "already suffices" line to single-series data.
4. Give an import that resolves: copy the file, or insert `<this-skill-dir>/scripts` into `sys.path`.

**Route:** small · plan · open on main · new.

#### G3 — The comparator degenerates on bayesian-workflow's own state-space shapes

**Where.**
- `compare_experiments.py:44-48` (observation count from the first variable) and `:59-60` (`az.compare` with no `var_name`).
- `bayesian-workflow/references/state-space.md:93` and `:103`, which recommend adding the likelihood through `numpyro.factor`.
- `model-comparison.md:29`, which says "LOO needs a pointwise `log_likelihood` group". `state-space.md` never mentions this; it has 0 hits for pointwise, log_likelihood, loo or elpd.

**Evidence** (re-measured on the verifier's own fixtures):
- **Scalar `factor`:** the log-likelihood variable has no observation dimension, so `observation_count` returns 0 for both variants and the guard passes. Result: exit 0 and a degenerate ranking (SE 0.0, weights 1.0 / 0.0).
- **Two observed sites:** an uncaught `TypeError: Found several log likelihood arrays … var_name cannot be None`.
- **Wrong criterion for forecasting:** the loo LFO vignette (<https://mc-stan.org/loo/articles/loo2-lfo.html>) and the CV-FAQ (<https://users.aalto.fi/~ave/CV-FAQ.html>) say LOO lets the future inform the past. For forecast tasks they recommend leave-future-out, or blocked K-fold with a joint log score. arviz-stats 1.3.3 ships `lfo_cv`; the pinned 1.3.2 has `loo_kfold`.

**Update.**
1. **Guards** (plannable now):
   - Refuse a log-likelihood variable with no observation dimension, or an observed count of 0, and name the fix: emit per-step pointwise terms rather than one summed `factor`. Add that warning beside both `factor` routes in `state-space.md`.
   - For multiple sites, do **not** pass `--var-name` through. That would rank a two-source nowcast on one source. Require one combined pointwise variable instead.
   - Add tests.
2. **Criterion** (belongs in the G-B spec): add a time-series comparison subsection to `model-comparison.md`. LOO is fine for interpolation and structure questions; for forecast decisions, rank by LFO or blocked K-fold. Let the comparator accept a precomputed per-variant ELPD (`--score lfo`).

**Route:** guards medium · plan; criterion with G-B. Open on main · new.
