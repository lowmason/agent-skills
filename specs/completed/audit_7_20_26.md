## Resolved — DEFECT (correctness; a correctly-loading skill gives wrong guidance)

- **C1 — `bayesian-workflow`'s mandatory prior-predictive recipe crashes.**
  `references/priors.md:215`, duplicated at `references/visualize.md:77`. Reproduced on the
  stack `SKILL.md:59` declares (arviz 1.2.0 / numpyro 0.21.0):
  `az.from_numpyro(prior=prior_pred, ...)` raises
  `ValueError: sample_dims must be provided if posterior is None`. Adding
  `sample_dims=['sample']` clears the raise but yields a DataTree whose only child is
  `prior` — no `prior_predictive` group — so the following
  `azp.plot_ppc_dist(idata_prior, group='prior_predictive')` fails too. This breaks
  `priors.md:206` ("This is mandatory. Never skip it.") and `SKILL.md:239`.
  **Fix:** replace both sites with a path verified to emit the group, and give a genuine
  pre-fit alternative (plot `prior_pred['y_obs']` directly, or assemble via `from_dict`) —
  `az.from_numpyro(mcmc, prior=prior_pred, ...)` works but requires a fit, which defeats a
  *prior* check. Also audit `SKILL.md:262` (`oos_pred = az.from_numpyro(posterior_predictive=...)`),
  same prior-only pattern, same expected failure. Run every edited snippet before shipping.

- **C2 — PIT shape interpretation self-contradicts across two references.**
  `references/model-criticism.md:127` reads U-shape/"frown" → underdispersed, over-confident;
  `references/visualize.md:201` reads the same "frown"/∪ → too broad, over-dispersed.
  `model-criticism.md:167` independently attaches ∪ to "posterior too narrow", so the glyph
  carries both meanings inside one file. `visualize.md:204` routes the reader from one to the
  other. Load-bearing: `scripts/check_diagnostics.py:302-314` branches on the strings
  `"over-confident"` and `"under-confident"`.
  **Fix direction NOT established — do not edit on this finding alone.** The shape→dispersion
  mapping legitimately *inverts* between a PIT histogram and a LOO-PIT ECDF-difference plot,
  and the two files may be describing different plot types, in which case each is locally
  correct and only the shared vocabulary is at fault. Determine which plot each file means,
  then declare one coordinate system and one source of truth. A wrong fix here silently
  corrupts the `check_diagnostics.py` branch.

  **Resolved 2026-07-20:** the inversion hypothesis was FALSE. Simulation at N=400k shows the
  shape→dispersion mapping is identical across histogram, density and coverage ΔECDF; the
  contradiction was purely lexical (a "frown" is ∩, not ∪, and each file paired the word with
  the wrong glyph). `model-criticism.md`'s SBC rank-histogram block was correct throughout, and
  `check_diagnostics.py` needed no change — it reads a numeric sign from `calibration_check.py`,
  never the prose, which is why years of contradictory docs never produced a wrong diagnosis.

- **C3 — `HalfCauchy` described as improper.** `SKILL.md:318` groups it under "Flat priors on
  scale parameters (`HalfCauchy`, improper)". It is proper (density `2/(πs(1+(x/s)²))` on
  x ≥ 0, integrates to 1) and is the canonical weakly-informative *replacement* for improper
  flat priors (Gelman 2006) — the line labels the cure as the disease. It is also not flat.
  The practical funnel advice is correct; `references/diagnostics.md:117` makes the same point
  without the false word. **Fix:** re-word to "heavy-tailed or near-flat priors on scale
  parameters (`HalfCauchy` — proper, but heavy-tailed with substantial mass near 0 — and
  genuinely improper flat priors)".

- **C4 — noncovered-employment composition wrong in the BLS hub.**

  references refute the hub: `references/ces.md:50` puts proprietors, the unincorporated
  self-employed, unpaid family workers, farm and private-household employment and the uniformed
  military *out of CES scope* (so they cannot be added back at benchmark), while
  `references/sae.md:449` gives the actual NCE population (certain student workers, interns,

  employment) and `references/ces.md:339` adds corporate officers. Impact amplified by
  `SKILL.md:29` ("Read the one(s) you need; do not load all nine") — a hub-only reader gets no
  correction. **Fix:** split the two gaps, using the categories the bundled references already
  use, and keep the "~95–97%" framing from the selector table at `SKILL.md:36`.

- **C5 — flat-file period-code rule omits the quarterly programs.**

- **C6 — the meta-skill contradicts the repo's own lint on the 1024-char cap.**

## Themes

1. **Domain content ages against its own declared stack.** `SKILL.md:59` promises "modern
   ArviZ >= 1.0"; no gate enforces it, and C1/C2/D2 are all runnable claims that were true
   against an older ArviZ. `verify_citations.py` proves the repo will mechanize this class of
   check for §-refs; nothing analogous exists for executable snippets or API surfaces.
2. **Hub-and-reference conflation.** Both BLS defects share a shape: the hub compresses a
   reference wrongly, and `SKILL.md:29` tells agents not to load the reference that would
   correct it. Any hub claim not derivable from a quotable reference line is unprotected.
3. **CLAUDE.md prose is the least-guarded surface.** D1, D3 and D4 are all things the repo
   already knows elsewhere (NOTICE, pytest output, `git ls-files`) — so the file agents read
   first carries the weakest guarantee.
4. **Counts and file lists hardcoded in prose drift on every addition.**
5. **Upstream adaptation residue.** D5 is superpowers text that was true in a plugin context
   with an always-loaded bootstrap skill. The `superpowers:` namespace is scrubbed *and* linted;
   the assumptions it carried were not.
6. **The meta-skill is not held to its own gate** (C6), and it governs everything else.

  `subagent-driven-development`'s gates or `brainstorming`'s HARD-GATE actually hold against an
  implementation-eager agent is behavioral, not textual.

  with `references/ces.md`, `sae.md`, `bed.md`. Strong evidence, but a claim wrong in *both* hub
  and reference would pass undetected.
- **Version pins float.** `uv run --with polars` resolves newest-at-runtime; snippet results are
  point-in-time.
- **Not assessed:** whether these are the right 25 skills, cross-skill routing quality under real
