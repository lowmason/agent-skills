## Purpose and scope
S7. Bring the repo to the parts of the survey that apply to it, in four themes the owner selected:
S8. 1. **Frontmatter conformance** — the lint accepts every Agent Skills spec field, separates spec keys from host extensions, and checks the shapes the spec defines (R1).
S9. 2. **Codex-visible openings** — description openings work under Codex's per-description truncation, and `writing-skills` records the measured fact (R2).
S10. 3. **Self-contained scripts** — every runnable bundled script carries a PEP 723 header and is invoked with `uv run` (R3).
S11. 4. **License travel** — each skill directory carries the license texts that apply to it, so a single-skill install keeps MIT's required notice (R4).
S12. Most of the survey is already true here and needs no work: `name` matches its directory and descriptions are within 1,024 characters (`build/check_frontmatter.py`); `install.py` links `skills/` into `~/.claude/skills` and the cross-runtime `~/.agents/skills`, with a `--copy` fallback; skill bodies name no runtime tool (`TodoWrite`, Skill/Task/Agent tool) and use no `$ARGUMENTS` or `` !`cmd` `` injection, and bundled paths use `<this-skill-dir>`; side-effect gates live in skill bodies; every command is `disable-model-invocation: true`.

## Decisions and alternatives
S24. 1. **Keep `skills/` as the canonical tree.** Moving it to `.agents/skills/` has a large blast radius (installer, tests, CLAUDE.md, symlinks) and buys nothing: the installer already links into every runtime's discovery path, which is the survey's own alternative.
S25. *Rejected.*
S26. 2. **No in-repo `.claude/skills` symlink.** The skills already load user-level from the same checkout; a project-level link would list each one twice.
S27. *Rejected.*
S28. 3. **No manual-only conversion of side-effecting skills.** `disable-model-invocation: true` removes a skill from the model's reach, which would break bare-name handoffs (`finishing-a-development-branch`, `using-git-worktrees`, and the others are invoked by name from other skills).
S29. Their side effects are already gated in their bodies, the survey's portable pattern.
S30. *Rejected.*
S31. 4. **Keep the "Use when…" description convention.** The survey suggests "Does X.
S32. Use when Y".
S33. `writing-skills`, the governing meta-skill, requires trigger-only descriptions on tested evidence that a workflow summary in the description lets agents skip the body.
S34. "Use when" already front-loads the trigger.
S35. *Rejected.*
S36. 5. **No description rewrites in this spec.** R2.1's review found none needed, and no trigger evals exist to catch a regression.
S37. The one exception is the angle-bracket fix (R1.5), which is wording-equivalent.
S38. 6. **The strict profile is a report, not the gate.** Both measured non-Claude runtimes load skills with host keys; strictness matters only for claude.ai uploads and `skills-ref`-style validators (R1.8).
S39. 7. **No secondary-source numbers become lint caps.** The survey's 1,536-character truncation, Codex's 2% / 8,000-character budget, and Claude Code's listing fraction stay out of the lint; it keeps the spec's 1,024 cap.
S40. Claude Code listing behavior is documented in `specs/guides/claude-code-customization-guide.md`.
S41. 8. **House PEP 723 form, not `#!/usr/bin/env -S uv run --script`.** A plain `#!/usr/bin/env python3` shebang keeps the script runnable by bare `python3` where uv is absent; `uv run <path>` reads the header either way.
S42. The two existing `build.py` headers are the template.
S43. 9. **All runnable scripts become self-contained**, including the three that read saved model artifacts.
S44. No single work venv pairs NumPyro with ArviZ, so the project interpreter can lack the imports these scripts need, and work repos that install `hooks/uv-guard.sh` deny bare `python …` anyway.
S45. 10. **Every skill bundles license text**, not only those with third-party content: one uniform rule, enforced byte-for-byte, at no context cost (the files are never referenced, so never loaded).

### R1 — Frontmatter conformance (`build/check_frontmatter.py`)
S46. R1.1 **Key sets.** Replace `ALLOWED_KEYS` with two named sets and allow their union in a `SKILL.md`:
S47. - `SPEC_KEYS = {name, description, license, compatibility, metadata, allowed-tools}`
S48. - `HOST_KEYS = {when_to_use, model, effort, context, disable-model-invocation}`
S49. R1.2 **`metadata`.** When present, a mapping whose keys and values are all strings.
S50. All current values pass.
S51. R1.3 **`compatibility`.** When present, a string of 1–500 characters after stripping.
S52. R1.4 **`license`.** Required in every `SKILL.md`, a non-empty string (repo policy, beyond the spec).
S53. The 13 superpowers skills gain `license: MIT` and
S54. ```yaml
metadata:
  author: 'Jesse Vincent'
  adapted_by: 'Lowell Mason'
  source: 'https://github.com/obra/superpowers'
```
S55. mirroring `bayesian-workflow`'s existing `author` / `adapted_by` pattern.
S56. R1.5 **No angle brackets.** `name` and `description` contain no `<` or `>`.
S57. Fix llm-wiki's trigger phrase `'verify <page>'` to `'verify a page'`.
S58. R1.6 **Invocation parity with Codex.** For a `SKILL.md`, `disable-model-invocation` must be a YAML boolean when present.
S59. A skill with `disable-model-invocation: true` must ship `agents/openai.yaml` that parses and sets `policy.allow_implicit_invocation: false`.
S60. Conversely, a skill whose `agents/openai.yaml` sets that policy to `false` must set `disable-model-invocation: true`.
S61. No skill trips this today; it exists so that the first manual-only skill cannot auto-fire in Codex.
S62. R1.7 **Body-length advisory.** A `SKILL.md` body (the lines after the closing frontmatter `---`) over 500 lines prints one `WARN` line to stderr and does not change the exit code.
S63. Today only `writing-skills` warns; splitting it is deferred.
S64. When Stage A adds this warning, it also adds a `skill-body-size` `[[check]]` to `build/cc_guide/conformance.toml` that maps `skills.overview` to it, with `enforced_by = 'check_frontmatter'` (conformance R6 P3).
S65. R1.8 **`--strict` profile.** `check_frontmatter.py --strict` additionally fails on any `HOST_KEYS` key in a `SKILL.md`, and on a `name` containing `claude` or `anthropic`.
S66. It is not part of the default gate.
S67. Expected result today: exactly `bayesian-workflow`, `tune-hyperparameters`, and `tech-debt` fail.
S68. Agents and commands are not Agent Skills and are unaffected.
S69. R1.9 The module docstring describes the new rules and the `--strict` flag, and CLAUDE.md's Commands section gains the `--strict` invocation with one line on when to use it (preparing a claude.ai upload or a spec-only validator run), under the `claude-md-size` check's 200-line limit (Sequencing, "Conformance register").

### R2 — Codex-visible openings
S70. R2.1 **Review verdict (recorded here, no rewrites).** Criterion: within its first 150 characters, a description names the skill's primary trigger, the task or symptom it exists for, so an agent shown only that prefix would load it for its canonical use.
S71. All 32 descriptions pass as of 2026-10-03.
S72. The closest calls are `creative-thinking` (its quoted examples carry the "fuzzy target" trigger) and the `clean-code` / `clean-coder` pair, whose openings both lead with editing Python.
S73. Both pass, so neither is rewritten.
S74. R2.2 **RED baseline micro-test for `writing-skills`.** Before any edit to `writing-skills`, run a baseline:
S75. - 5 reps, each a fresh agent given the current `writing-skills` description guidance (the control: no new wording).
S76. Each is asked to write a SKILL.md description for a synthetic skill that is not from this repo and has at least 8 trigger conditions, one of them designated in the scenario as primary.
S77. - Run from a session whose cwd was never this repo.
S78. - A rep passes if the designated primary trigger lies within the first 150 characters.
S79. The controller reads each output and records the verbatim 150-character prefix.
S80. - Record the scenario, prompts, outputs, and verdicts in `specs/red-baseline-description-openings-<YYYY-MM-DD>.md`, the house red-baseline format.
S81. R2.3 **Edit by outcome.**
S82. - **Baseline ≥ 4/5:** add only a factual note of 2–4 lines to `writing-skills`' "Token Efficiency" section.
S83. The note covers three points: Codex shortens every description when its listing exceeds its budget; the measured cut (156–164 characters with 93 skills listed, Codex 0.154, 2026-10-03); and how to re-measure (`codex debug prompt-input` from a directory outside any repo, reading the Skills list).
S84. No new rule.
S85. - **Baseline ≤ 3/5:** also add one checklist line ("the primary trigger falls within the first ~150 characters") and GREEN-test it: 5 reps with the new wording, at least 4/5 passing, recorded in the same red-baseline file.

### R3 — Self-contained scripts
S86. R3.1 **Inventory.** The runnable scripts are the `skills/*/scripts/*.py` files with a `__main__` guard.
S87. There are 16.
S88. Fourteen gain a header:
S89. - `bayesian-workflow`: `calibration_check.py`, `check_diagnostics.py`, `diagnose_model.py`
S90. - `describe-critique-methodology`: `check_decoupling.py`
S91. - `design-architecture`: `new_adr.py`
S92. - `explore-data`: `profile.py`
S93. - `llm-wiki`: `bootstrap_wiki.py`, `distill_sessions.py`, `distill_specs.py`, `lint_wiki.py`
S94. - `recommend-probabilistic-model`: `characterize.py`
S95. - `recommend-visualization`: `recommend.py`
S96. - `track-model-experiments`: `compare_experiments.py`
S97. - `writing-plans`: `deferred_stats.py`
S98. The two `build.py` scripts (`classification-codes`, `geographic-codes`) already conform.
S99. `tune-hyperparameters/scripts/time_series_cv.py` has no `__main__` guard; it is a library imported into the user's code and stays header-less.
S100. Bash scripts are out of scope.
S101. R3.2 **Header form.** Follow the `build.py` template exactly:
S102. - Line 1 is `#!/usr/bin/env python3`; add it where missing.
S103. - Then a `# /// script` block with single-quoted TOML strings, a `requires-python`, and a `dependencies` list (`[]` for stdlib-only scripts).
S104. R3.3 **`requires-python`.**
S105. - Use the lowest of `'>=3.11'`, `'>=3.12'`, `'>=3.13'` under which the test suite covering the script passes, run with `uv run --python 3.X` and that suite's CLAUDE.md dependencies.
S106. - Scripts covered by one suite share its floor, unless a failure is attributable to one script, which then alone takes the higher floor.
S107. - Prose floors that disagree with the header are aligned or removed (e.g. "Python ≥ 3.9" in `recommend-probabilistic-model` and `recommend-visualization`).
S108. The header and the skill's `compatibility` field become the statement of record.
S109. R3.4 **`dependencies`.**
S110. - Every third-party import, including function-level imports, is declared with a `>=` floor at the major version the suite currently resolves (e.g. `'polars>=1.0'`).
S111. No upper pins.
S112. - Imports inside a `try` whose handler catches `ImportError` or `ModuleNotFoundError` are optional and may be left undeclared.
S113. - Runtime backends that the script never imports but needs to read its inputs (e.g. `h5netcdf` for NetCDF) are added when R3.8's fixture run shows them needed.
S114. R3.5 **Invocations.**
S115. - Every documented invocation in `skills/**/*.md` of a path that resolves to one of the 16 scripts uses the form `uv run <path> [args]`, replacing `python`, `python3`, `uv run --no-project --python 3.13 python`, and `uv run --python 3.13 --with … python`.
S116. - Path forms in use: `<this-skill-dir>/scripts/x.py`, `<this-skill-dir>/../<skill>/scripts/x.py`, `$LLM_WIKI_ROOT/scripts/x.py` (the installed copies), `~/Projects/agent-skills/skills/llm-wiki/scripts/x.py` (llm-wiki's INSTALL.md), and repo-relative `skills/<skill>/scripts/build.py`.
S117. - Each skill with such an invocation gets this sentence once, near its first invocation: "Without uv, run the same path with `python3` in an environment that has the dependencies listed in the script's header."
S118. R3.6 **`compatibility`.** Every skill whose markdown runs a bundled script with `uv run` declares `compatibility: Requires uv to run bundled scripts (dependencies are declared inline); Python 3.X+.`
S119. Here 3.X is the highest `requires-python` floor among the scripts that skill invokes.
S120. That set includes `finishing-a-development-branch`, which runs `writing-plans`' `deferred_stats.py`.
S121. R3.7 **Lint, in `check_frontmatter.py`.** Each rule gets a RED test first.
S122. - A `skills/*/scripts/*.py` file with a `__main__` guard carries a PEP 723 block that parses with `tomllib` and has `requires-python` and `dependencies`.
S123. - In such a script, every non-stdlib, non-local import is declared in `dependencies`:
S124. - stdlib is detected via `sys.stdlib_module_names`;
S125. - local means a sibling module file in the same directory;
S126. - import names map to distributions through a small alias table, e.g. `yaml` → `pyyaml`;
S127. - R3.4's optional-import exemption applies.
S128. - No skill markdown invokes a resolving bundled-script path with bare `python` or `python3`, including line-continued forms (`python \` followed by the path on the next line).
S129. A path that does not resolve to a bundled script, such as `writing-skills/anthropic-best-practices.md`'s teaching example `scripts/migrate.py`, is not flagged.
S130. - A skill whose markdown runs a bundled script via `uv run` declares a `compatibility` value containing `uv`.
S131. R3.8 **Execution proof**, one time, recorded in the plan's completion notes.
S132. - From an empty scratch directory (a subdirectory such as `/tmp/bwprobe/`, never `/tmp` itself), each of the 16 scripts runs `uv run <absolute-path>` on a minimal real input that exercises its main code path.
S133. - `--help` alone is enough only for a script with no input-reading path.
S134. - The three ArviZ-reading scripts (`diagnose_model.py`, `calibration_check.py`, `compare_experiments.py`) each read a small saved InferenceData fixture.
S135. - One script is also run from inside a directory holding an unrelated `pyproject.toml`.
S136. This proves the header isolates it from the project environment.
S137. R3.9 The dependency-drift check still passes.
S138. Invocation text changes, but no cross-skill reference is added or dropped; finishing → `writing-plans`' `deferred_stats.py` is an existing `DEPENDENCIES` edge.
